# Docker Images and Helm Charts

This repository keeps self-hosted application packaging in one place:

| Area              | Directory                      | What lives there                                                                                       |
| ----------------- | ------------------------------ | ------------------------------------------------------------------------------------------------------ |
| Docker containers | [`containers/`](./containers/) | Repo-owned Docker build contexts, runtime entrypoints, compose examples, and container-specific notes. |
| Helm charts       | [`charts/`](./charts/)         | Helm charts for deploying the packaged applications and related third-party services to Kubernetes.    |

The root README intentionally stays short. Use the directory-level READMEs for the committed catalog:

- [`containers/README.md`](./containers/README.md) lists the committed container build contexts.
- [`charts/README.md`](./charts/README.md) lists the committed Helm charts and chart repository publishing flow.

## Documentation automation

- Helm chart READMEs are generated by the existing [`norwoodj/helm-docs`](https://github.com/norwoodj/helm-docs) pre-commit hook configured in [`.pre-commit-config.yaml`](./.pre-commit-config.yaml).
- Container catalog documentation is maintained in [`containers/README.md`](./containers/README.md).
  - **TODO**: A Dockerfile-focused generator such as [`dock-docs`](https://github.com/northcutted/dock-docs) may be worth evaluating later, but this repository does not currently wire one into pre-commit.

## Development setup

- Install pre-commit hooks: `pre-commit install`.

## Maintenance commands

| Command                                   | Purpose                                                      |
| ----------------------------------------- | ------------------------------------------------------------ |
| `detect-secrets scan > .secrets.baseline` | Rebuild the secrets baseline when intentionally updating it. |
